## Advanced Function Applications

In the previous chapter, we explored higher-order functions in Python, and you should now have a deeper understanding of how to define and use functions. In this chapter, we will continue to cover function-related topics: Python's signature syntax feature called decorators, and recursive function calls.

### Decorators

In Python, a decorator is a syntactic construct that **uses one function to decorate another function and provide it with additional capabilities**. A decorator itself is a function whose parameter is the function being decorated, and whose return value is a function with the added decoration. From this description, you can tell that a decorator is a higher-order function — both its parameter and return value are functions. However, the concept of decorators can be quite headache-inducing for beginners. Let's start with a simple example to illustrate what decorators do. Suppose we have two functions named `download` and `upload` for downloading and uploading files, as shown below.

```python
import random
import time


def download(filename):
    """Download a file"""
    print(f'Starting to download {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download complete.')


def upload(filename):
    """Upload a file"""
    print(f'Starting to upload {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload complete.')


download('MySQL从删库到跑路.avi')
upload('Python从入门到住院.pdf')
```

> **Note**: The code above simulates the time required for downloading and uploading files by sleeping for a random duration — it does not actually perform network uploads or downloads. Implementing network file uploads and downloads in Python is also very simple, and we will cover the relevant knowledge later.

Now there's a new requirement: we want to know how long the `download` and `upload` function calls actually take. How should we implement this? Many of you have probably already thought of it — we can record a timestamp when the function starts executing, record another when the function call ends, and subtract the two to get the download or upload time, as shown below.

```python
start = time.time()
download('MySQL从删库到跑路.avi')
end = time.time()
print(f'Time elapsed: {end - start:.2f} seconds')
start = time.time()
upload('Python从入门到住院.pdf')
end = time.time()
print(f'Time elapsed: {end - start:.2f} seconds')
```

With the code above, we can record the time spent during downloads and uploads. But have you noticed that the code for recording time, computing, and displaying execution time is all duplicate code? Experienced programmers know that **duplicate code is the root of all evil**. Is there a way to record function execution time in a simple and elegant way without writing duplicate code? In Python, decorators are the best solution for this kind of problem. With decorator syntax, we can encapsulate the timing code (which is unrelated to the original business logic of uploading and downloading) into a function. If `upload` and `download` need to record time, we simply apply the decorator to these two functions. Since we mentioned that a decorator is a higher-order function with both a function parameter and a function return value, let's call our timing decorator `record_time`. Its overall structure should look like the code below.

```python
def record_time(func):

    def wrapper(*args, **kwargs):

        result = func(*args, **kwargs)

        return result

    return wrapper
```

As you can see, the parameter `func` of `record_time` represents the function being decorated. The `wrapper` function defined inside is the function with the added decoration — it executes the decorated function `func` and eventually returns its result. Notice that I left two blank lines at lines 4 and 6, indicating that we can add code at those locations to implement additional functionality. The `record_time` function ultimately returns this decorated `wrapper` function, which replaces the original function `func`. After the original function `func` is decorated by `record_time`, when we call it, we are actually calling `wrapper`, which is how we get the extra capability. The `wrapper` function's parameters are special — since we are using `wrapper` to replace the original `func`, but we don't know what parameters `func` accepts, we use variable arguments and keyword arguments to accept everything, then pass them all unchanged when calling `func`. It's also worth emphasizing that Python supports nested function definitions — as seen above, we can define `wrapper` inside `record_time`. This is not supported in many other programming languages.

Once you understand this structure, we can add the timing functionality to this decorator, as shown below.

```python
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        # Record start time before executing the decorated function
        start = time.time()
        # Execute the decorated function and get its return value
        result = func(*args, **kwargs)
        # Record end time after executing the decorated function
        end = time.time()
        # Calculate and display the execution time of the decorated function
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        # Return the decorated function's return value
        return result

    return wrapper
```

Writing a decorator takes some effort, but it's a one-time investment that pays off repeatedly. Whenever there's a need to record function execution time in the future, we just need to apply this decorator. There are two ways to use the decorator function. The first is to call the decorator function directly, pass in the function to be decorated, and capture the return value. We can use this return value to replace the original function, so that when calling it, we already have the extra capability (recording execution time). Try the code below to see for yourself.

```python
download = record_time(download)
upload = record_time(upload)
download('MySQL从删库到跑路.avi')
upload('Python从入门到住院.pdf')
```

In Python, there is an even more convenient **syntactic sugar** for using decorators (a syntactic feature added to a language that doesn't affect functionality but makes code more convenient and readable — hence the name "syntactic sugar"). You can place `@decorator_function` directly above the function being decorated, which has the same effect as the code above. Let's list the complete code for you to see how to define and use decorators.

```python
import random
import time


def record_time(func):

    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Starting to download {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download complete.')


@record_time
def upload(filename):
    print(f'Starting to upload {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload complete.')


download('MySQL从删库到跑路.avi')
upload('Python从入门到住院.pdf')
```

In the code above, we added decorators to the `download` and `upload` functions using decorator syntactic sugar. After decoration, `download` and `upload` are actually the `wrapper` function returned in the decorator, so calling them is calling `wrapper`, which provides the timing functionality.

If at some point in the code, we want to remove the decorator's effect and execute the original function, we need to do a little extra work when defining the decorator function. The `wraps` function from the `functools` module in Python's standard library is also a decorator. Placing it on the `wrapper` function helps preserve the original function before decoration. When you need to cancel the decorator, you can access the original undecorated function via the decorated function's `__wrapped__` attribute.

```python
import random
import time

from functools import wraps


def record_time(func):

    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f'{func.__name__} execution time: {end - start:.2f} seconds')
        return result

    return wrapper


@record_time
def download(filename):
    print(f'Starting to download {filename}.')
    time.sleep(random.random() * 6)
    print(f'{filename} download complete.')


@record_time
def upload(filename):
    print(f'Starting to upload {filename}.')
    time.sleep(random.random() * 8)
    print(f'{filename} upload complete.')


# Calling the decorated functions will record execution time
download('MySQL从删库到跑路.avi')
upload('Python从入门到住院.pdf')
# Cancel the decorator's effect and don't record execution time
download.__wrapped__('MySQL必知必会.pdf')
upload.__wrapped__('Python从新手到大师.pdf')
```

**Decorator functions themselves can also be parameterized** — in simple terms, decorators can be customized through parameters passed by the caller. We will explain this in more detail when we encounter it later.

### Recursive Calls

Python allows nested function definitions and mutual function calls, and a function can also call itself directly or indirectly. When a function calls itself, this is called a recursive call. What is recursion useful for? In reality, many problems have definitions that are themselves recursive. For example, the factorial we discussed earlier — the factorial of a non-negative integer `N` is `N` multiplied by the factorial of `N-1`, i.e., $\small{N! = N \times (N-1)!}$. Both sides of the definition involve the factorial concept, making it a recursive definition. Since this is the case, we can write a factorial function using recursive calls, as shown below.

```python
def fac(num):
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

In the code above, the `fac` function calls `fac` again within itself — this is a recursive call. The `if` condition on line 2 is the recursive convergence condition — it defines when to stop the recursion. For factorials, if we've computed down to the factorial of `0` or `1`, we stop recursing and directly return `1`. Line 4's `num * fac(num - 1)` is the recursive formula, which is the recursive definition of factorial. Let's briefly analyze what happens when computing `5!` using `fac(5)`.

```python
# Recursive calls push functions onto the stack
# 5 * fac(4)
# 5 * (4 * fac(3))
# 5 * (4 * (3 * fac(2)))
# 5 * (4 * (3 * (2 * fac(1))))
# Recursion stops, functions pop off the stack
# 5 * (4 * (3 * (2 * 1)))
# 5 * (4 * (3 * 2))
# 5 * (4 * 6)
# 5 * 24
# 120
print(fac(5))    # 120
```

Note that function calls use a data structure in memory called a "stack" to save the current execution context. After a function call finishes, this stack structure restores the previous context. A stack is a last-in-first-out (LIFO) data structure, meaning the first function pushed onto the stack is the last to return, and the last function pushed is the first to return. For example, if a function `a` calls function `b`, and `b` calls function `c`, then `a` is pushed first and `c` is popped first. Each time a function is called, the stack grows by one stack frame, which stores the current execution context. When a function returns, the stack shrinks by one frame. Typically, stack space in memory is small, so if there are too many recursive calls, it will cause a stack overflow. Therefore, **recursive calls must ensure fast convergence**. You can try executing `fac(5000)` to see if you get a `RecursionError` with the message: `maximum recursion depth exceeded in comparison` — this is essentially a stack overflow.

If you're using the official Python interpreter (CPython), the default maximum depth for function call stacks is `1000` levels. Exceeding this depth will trigger the `RecursionError` mentioned above. You can use the `setrecursionlimit` function from the `sys` module to change the maximum recursion depth, but we don't recommend this. Making recursion converge quickly is what you should focus on; otherwise, you should consider using iterative loops instead of recursion.

Let's revisit another example — generating the Fibonacci sequence. Since the first two numbers in the Fibonacci sequence are both `1`, and from the third number onward, each number is the sum of the two preceding numbers, we can express this as `f(n) = f(n - 1) + f(n - 2)`. This is obviously a recursive definition, so we can use the following recursive function to compute the nth Fibonacci number.

```python
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 21):
    print(fib1(i))
```

A word of caution: although the code above for computing Fibonacci numbers looks very simple and clear, its execution performance is quite poor. Try changing the second argument of `range` in the `for` loop to `51` (i.e., output the first 50 Fibonacci numbers) and see how long it takes — feel free to share your execution time in the comments. As for why it's so slow, you can think about the reason yourself. Clearly, using an iterative approach to generate the Fibonacci sequence is a better choice, as shown below.

```python
def fib2(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

Additionally, we can use the `lru_cache` function from the `functools` module in Python's standard library to optimize the recursive code above. The `lru_cache` function is a decorator that, when applied to the `fib1` function, caches the function's results to avoid a large number of redundant computations during recursive calls. This gives the code a "blazing fast" performance improvement. Try outputting the first 50 Fibonacci numbers and see how long the code takes with the decorator applied — see you in the comments!

```python
from functools import lru_cache


@lru_cache()
def fib1(n):
    if n in (1, 2):
        return 1
    return fib1(n - 1) + fib1(n - 2)


for i in range(1, 51):
    print(i, fib1(i))
```

> **Tip**: `lru_cache` is a parameterized decorator, which is why line 4 uses the `lru_cache` decorator syntactic sugar with parentheses after it. The `lru_cache` function has a very important parameter called `maxsize`, which defines the size of the cache space, with a default value of 128.

###  Summary

Decorators are a signature syntax feature in Python that **can enhance existing functions** — a very useful programming technique. On the other hand, recursive function calls can simplify complex problems at the code level, but **recursion must pay attention to the convergence condition and the recursive formula**. Finding the recursive formula is what makes recursion possible, and the convergence condition ensures that the recursion can stop. Function calls use stack space in memory to save and restore execution contexts. Stack space is typically small, so **if recursion does not converge quickly, it is very likely to cause a stack overflow error, crashing the program**.
