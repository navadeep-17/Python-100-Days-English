## Advanced Object-Oriented Programming

In the previous lesson, we covered some basics of object-oriented programming in Python. In this lesson, we will continue discussing topics related to object-oriented programming.

### Visibility and Property Decorators

In many object-oriented programming languages, object attributes are usually set as private or protected members — in simple terms, direct access to these attributes is not allowed. Object methods are usually public, because public methods are the messages that objects can receive and the calling interfaces exposed to the outside world — this is the concept of access visibility. In Python, you can indicate the access visibility of an attribute by adding underscore prefixes to the attribute name. For example, `__name` indicates a private attribute, and `_name` indicates a protected attribute, as shown below.

```python
class Student:

    def __init__(self, name, age):
        self.__name = name
        self.__age = age

    def study(self, course_name):
        print(f'{self.__name} is studying {course_name}.')


stu = Student('王大锤', 20)
stu.study('Python Programming')
print(stu.__name)  # AttributeError: 'Student' object has no attribute '__name'
```

The last line of the code above raises an `AttributeError` exception with the message: `'Student' object has no attribute '__name'`. This shows that the `__name` attribute, prefixed with `__`, is effectively private — it cannot be accessed directly from outside the class, but it can be accessed within the class's `study` method via `self.__name`. It should be noted that most Python developers, when defining classes, typically do not choose to make object attributes private or protected. As the famous saying goes: "**We are all consenting adults here**" — adults can take responsibility for their own actions, without needing Python itself to restrict access visibility. In fact, most programmers believe that **openness is better than closure**, and making object attributes private is not an essential requirement. Therefore, Python does not enforce the strictest restrictions at the semantic level. In other words, if you really want to, you can still access the private attribute `__name` using `stu._Student__name` — interested readers can try it themselves.

### Dynamic Attributes

Python is a dynamic language. Wikipedia defines dynamic languages as: "languages that can change their structure at runtime, such as introducing new functions, objects, or even code, or deleting existing functions or making other structural changes." Dynamic languages are very flexible. Python and JavaScript, two of today's most popular languages, are both dynamic languages. Languages like PHP and Ruby are also dynamic, while C and C++ are not.

In Python, we can dynamically add attributes to objects. This is a privilege of Python as a dynamically typed language, as shown below. It should be noted that an object's methods are essentially attributes of the object as well. If you send a message to an object that it cannot receive, the exception raised is still `AttributeError`.

```python
class Student:

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('王大锤', 20)
stu.sex = '男'  # Dynamically add a sex attribute to the student object
```

If you don't want attributes to be dynamically added to objects, you can use Python's `__slots__` magic. For the `Student` class, you can specify `__slots__ = ('name', 'age')` in the class body, so that `Student` objects can only have the `name` and `age` attributes. Attempting to dynamically add other attributes will raise an exception, as shown below.

```python
class Student:
    __slots__ = ('name', 'age')

    def __init__(self, name, age):
        self.name = name
        self.age = age


stu = Student('王大锤', 20)
# AttributeError: 'Student' object has no attribute 'sex'
stu.sex = '男'
```

### Static Methods and Class Methods

The methods we defined in classes earlier are all instance methods — in other words, these methods are messages that objects can receive. Besides instance methods, a class can also have static methods and class methods. These two types of methods are messages sent to the class itself. In the object-oriented world, everything is an object — every class we define is also an object, and static methods and class methods are messages sent to class objects. So what kind of messages would be sent directly to a class object?

Here's an example: define a triangle class that constructs a triangle by passing in three side lengths, and provide methods to calculate the perimeter and area. Computing the perimeter and area are definitely methods of triangle objects — no question about it. But when creating a triangle object, the three side lengths passed in may not be able to form a triangle. We could first write a method to validate whether the given three side lengths can form a triangle. This kind of method is clearly not an instance method, because the triangle object hasn't been created yet when we call it. We can design such methods as static methods or class methods — meaning these methods are not sent to triangle objects but to the triangle class, as shown below.

```python
class Triangle(object):
    """Triangle"""

    def __init__(self, a, b, c):
        """Initialization method"""
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        """Check if three side lengths can form a triangle (static method)"""
        return a + b > c and b + c > a and a + c > b

    # @classmethod
    # def is_valid(cls, a, b, c):
    #     """Check if three side lengths can form a triangle (class method)"""
    #     return a + b > c and b + c > a and a + c > b

    def perimeter(self):
        """Calculate perimeter"""
        return self.a + self.b + self.c

    def area(self):
        """Calculate area"""
        p = self.perimeter() / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5


if Triangle.is_valid(3, 4, 5):
    t = Triangle(3, 4, 5)
    print(f'Perimeter: {t.perimeter()}')
    print(f'Area: {t.area()}')
else:
    print('Invalid side lengths!!!')
```

The code above uses the `staticmethod` decorator to declare `is_valid` as a static method of the `Triangle` class. To declare a class method, you can use the `classmethod` decorator (as shown in lines 15-18 of the code above). You can call both static methods and class methods using the `ClassName.method_name` syntax. The difference is that a class method's first parameter is the class object itself, while a static method has no such parameter. To summarize briefly: **instance methods, class methods, and static methods can all be called via "ClassName.method_name". The difference lies in whether the first parameter is a regular object, a class object, or no message-receiving object at all.** Static methods can generally also be written as standalone functions since they are not bound to any specific object.

Here's a supplementary note: we can add a `property` decorator (a Python built-in type) to the perimeter and area methods of the triangle. This turns `perimeter` and `area` into properties of the `Triangle` class — they are no longer accessed by calling methods, but by directly accessing them as object attributes. The modified code is shown below.

```python
class Triangle(object):
    """Triangle"""

    def __init__(self, a, b, c):
        """Initialization method"""
        self.a = a
        self.b = b
        self.c = c

    @staticmethod
    def is_valid(a, b, c):
        """Check if three side lengths can form a triangle (static method)"""
        return a + b > c and b + c > a and a + c > b

    @property
    def perimeter(self):
        """Calculate perimeter"""
        return self.a + self.b + self.c

    @property
    def area(self):
        """Calculate area"""
        p = self.perimeter / 2
        return (p * (p - self.a) * (p - self.b) * (p - self.c)) ** 0.5


if Triangle.is_valid(3, 4, 5):
    t = Triangle(3, 4, 5)
    print(f'Perimeter: {t.perimeter}')
    print(f'Area: {t.area}')
else:
    print('Invalid side lengths!!!')
```

### Inheritance and Polymorphism

Object-oriented programming languages support creating new classes based on existing classes, thereby reducing duplicate code. The class providing the inherited information is called the parent class (superclass, base class), and the class receiving the inherited information is called the child class (derived class, subclass). For example, if we define a student class and a teacher class, we'll find a lot of duplicate code — these duplicate parts are the common attributes and behaviors of teachers and students as people. So in this case, we should first define a `Person` class, then derive the teacher and student classes from it through inheritance, as shown below.

```python
class Person:
    """Person"""

    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        print(f'{self.name} is eating.')

    def sleep(self):
        print(f'{self.name} is sleeping.')


class Student(Person):
    """Student"""

    def __init__(self, name, age):
        super().__init__(name, age)

    def study(self, course_name):
        print(f'{self.name} is studying {course_name}.')


class Teacher(Person):
    """Teacher"""

    def __init__(self, name, age, title):
        super().__init__(name, age)
        self.title = title

    def teach(self, course_name):
        print(f'{self.name} ({self.title}) is teaching {course_name}.')



stu1 = Student('白元芳', 21)
stu2 = Student('狄仁杰', 22)
tea1 = Teacher('武则天', 35, 'Associate Professor')
stu1.eat()
stu2.sleep()
tea1.eat()
stu1.study('Python Programming')
tea1.teach('Python Programming')
stu2.study('Introduction to Data Science')
```

The syntax for inheritance is to specify the current class's parent class in the parentheses after the class name when defining the class. If a class is defined without specifying a parent class, the default parent class is the `object` class. `object` is the top-level class in Python, which means all classes are its subclasses — either directly or indirectly inheriting from it. Python allows multiple inheritance, meaning a class can have one or more parent classes. We will discuss multiple inheritance in more detail later. In a child class's initialization method, we can call the parent class's initialization method using `super().__init__()`. The `super` function is a Python built-in function specifically designed to get the parent class object of the current object. From the code above, you can see that in addition to inheriting attributes and methods from the parent class, child classes can also define their own unique attributes and methods, so child classes have more capabilities than parent classes. In real-world development, we often replace parent class objects with child class objects — this is a common practice in object-oriented programming, also known as the "Liskov Substitution Principle."

After inheriting methods from the parent class, child classes can also override (re-implement) those methods. Different child classes can provide different implementation versions of the same parent class method, and such methods will exhibit polymorphic behavior at runtime (calling the same method, but doing different things). Polymorphism is the most essential part of object-oriented programming, and also the most difficult for beginners to understand and apply flexibly. We will use dedicated examples in the next chapter to explain this concept.

### Summary

Python is a dynamically typed language where objects can have attributes added dynamically. An object's methods are also attributes — they just happen to correspond to callable functions. In the object-oriented world, **everything is an object**. The classes we define are also objects, so **classes can also receive messages** — the corresponding methods are class methods or static methods. Through inheritance, we **can create new classes from existing classes**, achieving code reuse.
