## File I/O and Exception Handling

In real-world development, you will often encounter scenarios that require data persistence. Persistence refers to transferring data from a storage medium that cannot retain data for a long time (usually memory) to one that can (usually a hard drive). The most straightforward and simple way to achieve data persistence is to save data to **files** through the **file system**.

A computer's **file system** is a method for storing and organizing computer data that makes accessing and locating data easy. The file system uses the abstract logical concepts of **files** and **tree-structured directories** instead of the data block concepts of physical devices such as hard drives, optical discs, and flash drives. When users save data using the file system, they don't need to worry about which data block on the hard drive the data is actually stored in -- they only need to remember the file path and file name. Before writing new data, users don't need to worry about which data blocks on the hard drive are unused; the management of storage space (allocation and deallocation) on the hard drive is handled automatically by the file system, and users only need to remember which file the data was written to.

### Opening and Closing Files

With a file system, we can conveniently read and write data through files. In Python, performing file operations is very simple. We can use Python's built-in `open` function to open files. When using the `open` function, we can specify the **file name**, **operation mode**, and **character encoding** through the function's parameters, and then we can perform read and write operations on the file. The operation mode mentioned here refers to what kind of file to open (character file or binary file) and what operation to perform (read, write, or append), as shown in the table below.

| Mode  | Description                                      |
| ----- | ------------------------------------------------ |
| `'r'` | Read (default)                                   |
| `'w'` | Write (truncates existing content first)         |
| `'x'` | Write, raises an exception if the file exists    |
| `'a'` | Append, writes content to the end of the file    |
| `'b'` | Binary mode                                      |
| `'t'` | Text mode (default)                              |
| `'+'` | Update (both read and write)                     |

When using the `open` function, if the file being opened is a character file (text file), you can specify the character encoding for reading and writing through the `encoding` parameter. If you're not familiar with the concepts of character encoding and character sets, you can read the article [Character Sets and Character Encodings](https://www.cnblogs.com/skynet/archive/2011/05/03/2035105.html) -- we won't go into detail about it here.

After successfully opening a file with the `open` function, a file object is returned. Through this object, we can perform read and write operations on the file. If opening the file fails, the `open` function will raise an exception, which will be explained later. To close an opened file, you can use the file object's `close` method, which releases the file when the file operation is complete.

### Reading and Writing Text Files

When opening a text file with the `open` function, you need to specify the file name and set the file's operation mode to `'r'`. If not specified, the default value is also `'r'`. If you need to specify character encoding, you can pass in the `encoding` parameter. If not specified, the default value is `None`, which means the operating system's default encoding will be used when reading the file. It's important to note that if the encoding used when saving the file is not consistent with the encoding specified by the `encoding` parameter, the file read may fail due to decoding errors.

The following example demonstrates how to read a plain text file (a file that generally consists only of natively encoded characters; unlike rich text, plain text does not contain character style control elements and can be read directly by the simplest text editors).

```python
file = open('致橡树.txt', 'r', encoding='utf-8')
print(file.read())
file.close()
```

In addition to using the file object's `read` method to read a file, you can also use a `for-in` loop to read line by line, or use the `readlines` method to read the file into a list container line by line, as shown in the code below.

```python
file = open('致橡树.txt', 'r', encoding='utf-8')
for line in file:
    print(line, end='')
file.close()

file = open('致橡树.txt', 'r', encoding='utf-8')
lines = file.readlines()
for line in lines:
    print(line, end='')
file.close()
```

If you want to write content to a file, you can use `w` or `a` as the operation mode when opening the file. The former truncates the previous text content and writes new content, while the latter appends new content to the end of the existing content.

```python
file = open('致橡树.txt', 'a', encoding='utf-8')
file.write('\nTitle: "To the Oak Tree"')
file.write('\nAuthor: Shu Ting')
file.write('\nDate: March 1977')
file.close()
```

### Exception Handling Mechanism

Please note the code above: if the file specified by the `open` function does not exist or cannot be opened, an exception will be raised, causing the program to crash. To make the code robust and fault-tolerant, we can **use Python's exception mechanism to appropriately handle code that may encounter issues at runtime**. There are five keywords related to exceptions in Python: `try`, `except`, `else`, `finally`, and `raise`. Let's look at the code below first, and then we'll explain the usage of these keywords.

```python
file = None
try:
    file = open('致橡树.txt', 'r', encoding='utf-8')
    print(file.read())
except FileNotFoundError:
    print('Unable to open the specified file!')
except LookupError:
    print('An unknown encoding was specified!')
except UnicodeDecodeError:
    print('Decoding error while reading the file!')
finally:
    if file:
        file.close()
```

In Python, we can place code that might encounter issues at runtime inside a `try` block. After `try`, you can follow with one or more `except` blocks to catch exceptions and handle them accordingly. For example, in the code above, a `FileNotFoundError` is raised when the file is not found, a `LookupError` is raised when an unknown encoding is specified, and a `UnicodeDecodeError` is raised when the file cannot be decoded with the specified encoding during reading. So we follow `try` with three `except` blocks to handle these three different exception scenarios. After the `except` blocks, we can also add an `else` block, which executes when no exception occurs in the `try` block. The code in `else` will not be caught by exception handling, meaning that if an exception occurs, the program will terminate with an exception report. Finally, we use a `finally` block to close the opened file and release the external resources acquired by the program. Since the code in the `finally` block executes regardless of whether the program runs normally or encounters an exception -- even if the `exit` function from the `sys` module is called to terminate the Python program, the code in the `finally` block will still execute (because the essence of the `exit` function is to raise a `SystemExit` exception) -- we call the `finally` block the "always-execute block," and it is best suited for releasing external resources.

From the inheritance structure above, we can see that all exceptions in Python are subtypes of `BaseException`, which has four direct subclasses: `SystemExit`, `KeyboardInterrupt`, `GeneratorExit`, and `Exception`. Among them, `SystemExit` indicates the interpreter is requesting to exit, `KeyboardInterrupt` means the user interrupted program execution (by pressing `Ctrl+C`), and `GeneratorExit` indicates a generator has issued an exception notification to exit. It's okay if you don't understand these exceptions -- just keep learning. It's worth mentioning the `Exception` class, which is the parent type for common exception types. Many exceptions directly or indirectly inherit from the `Exception` class. If Python's built-in exception types don't meet the needs of your application, you can define custom exception types, which should also directly or indirectly inherit from the `Exception` class. You can also override or add methods as needed.

In Python, you can use the `raise` keyword to raise an exception (throw an exception object), and the caller can catch and handle the exception through the `try...except...` structure. For example, in a function, when the execution conditions are not met, you can raise an exception to inform the caller about the problem, and the caller can recover from the exception by catching and handling it. The code for defining and raising an exception is shown below.

```python
class InputError(ValueError):
    """Custom exception type"""
    pass


def fac(num):
    """Calculate factorial"""
    if num < 0:
        raise InputError('Can only calculate factorial of non-negative integers')
    if num in (0, 1):
        return 1
    return num * fac(num - 1)
```

Calling the factorial function `fac`, we catch the input error exception through the `try...except...` structure and print the exception object (displaying the exception message). If the input is correct, the factorial is calculated and the program ends.

```python
flag = True
while flag:
    num = int(input('n = '))
    try:
        print(f'{num}! = {fac(num)}')
        flag = False
    except InputError as err:
        print(err)
```

### Context Manager Syntax

For the file object returned by the `open` function, you can also use the `with` context manager syntax to automatically call the file object's `close` method after the file operation is complete. This makes the code simpler and more elegant because you no longer need to write a `finally` block to close the file and release resources. It's important to note that not all objects can be used with the `with` context syntax -- only objects that conform to the **context manager protocol** (having `__enter__` and `__exit__` magic methods) can use this syntax. Python's standard library `contextlib` module also provides support for the `with` context syntax, which we will explain later when needed.

The code rewritten using `with` context syntax is shown below.

```python
try:
    with open('致橡树.txt', 'r', encoding='utf-8') as file:
        print(file.read())
except FileNotFoundError:
    print('Unable to open the specified file!')
except LookupError:
    print('An unknown encoding was specified!')
except UnicodeDecodeError:
    print('Decoding error while reading the file!')
```

### Reading and Writing Binary Files

Reading and writing binary files is similar to reading and writing text files, but note that when using the `open` function, if you want to read, the operation mode is `'rb'`, and if you want to write, the operation mode is `'wb'`. Another point is that when reading and writing text files, the return value of the `read` method and the parameter of the `write` method are `str` objects (strings), while when reading and writing binary files, the return value of `read` and the parameter of `write` are `bytes-like` objects (byte strings). The following code copies an image file named `guido.jpg` in the current path to a file named `吉多.jpg`.

```python
try:
    with open('guido.jpg', 'rb') as file1:
        data = file1.read()
    with open('吉多.jpg', 'wb') as file2:
        file2.write(data)
except FileNotFoundError:
    print('The specified file could not be opened.')
except IOError:
    print('An error occurred while reading/writing the file.')
print('Program execution complete.')
```

If the image file to be copied is very large, reading the entire file content into memory at once may cause significant memory overhead. To reduce memory usage, you can pass a `size` parameter to the `read` method to specify the number of bytes to read each time, and complete the operation through a loop of reading and writing, as shown in the code below.

```python
try:
    with open('guido.jpg', 'rb') as file1, open('吉多.jpg', 'wb') as file2:
        data = file1.read(512)
        while data:
            file2.write(data)
            data = file1.read()
except FileNotFoundError:
    print('The specified file could not be opened.')
except IOError:
    print('An error occurred while reading/writing the file.')
print('Program execution complete.')
```

### Summary

Through file read and write operations, we can achieve data persistence. In Python, you can obtain a file object through the `open` function and perform file read and write operations through the file object's `read` and `write` methods. Programs may encounter unpredictable exceptions at runtime, and Python's exception mechanism can be used to handle these situations. Python's exception mechanism mainly consists of five core keywords: `try`, `except`, `else`, `finally`, and `raise`. The `except` statement after `try` is not mandatory, nor is the `finally` statement, but at least one of them must be present. There can be one or more `except` statements, and multiple `except` blocks will match specified exceptions in the order they are written -- if an exception has been handled, subsequent `except` statements will not be entered. You can also specify multiple exception types in a tuple within an `except` statement for catching. If no exception type is specified after `except`, it will catch all exceptions by default. After catching an exception, you can use `raise` to re-raise it, but it is not recommended to catch and re-raise the same exception. It is also not recommended to catch all exceptions without understanding the logic, as this may mask serious problems in the program. Finally, one important point: **do not use the exception mechanism to handle normal business logic or control program flow** -- in other words, do not abuse the exception mechanism. This is a common mistake made by beginners.
