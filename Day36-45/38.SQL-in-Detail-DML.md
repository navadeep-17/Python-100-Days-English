## SQL in Detail - DML

Continuing with the school course selection system database created in the previous lesson, we will explain the usage of DML. DML can help insert data into two-dimensional tables (`insert` operation), delete data from two-dimensional tables (`delete` operation), and update data in two-dimensional tables (`update` operation). Before executing DML, let us first switch to the `school` database using the `use` command below.

```SQL
USE `school`;
```

### Insert Operation

As the name suggests, `insert` is used to insert rows into a two-dimensional table. The insertion methods include: inserting a complete row, inserting part of a row, inserting multiple rows, and inserting the results of a query. We use the following SQL to add a college to the college table.

```SQL
INSERT INTO `tb_college`
VALUES
    (DEFAULT, '计算机学院', '学习计算机科学与技术的地方');
```

Since the primary key of the college table is an auto-increment field, the SQL above uses `default` to indicate that the column should use its default value. We can also accomplish the same operation using the method below.

```SQL
INSERT INTO `tb_college` (`col_name`, `col_intro`)
VALUES
    ('计算机学院', '学习计算机科学与技术的地方');
```

We recommend the latter approach, which specifies which fields to assign values to. This allows you to assign values in a different order than the one defined when creating the table - you can assign values according to the order given in the tuple before `values`. However, note that except for fields that allow `null` and fields with default values, all other fields must be listed and assigned values in the tuple after `values`. If you want to insert multiple records at once, you can follow `values` with multiple tuples to achieve batch insertion, as shown below.

```SQL
INSERT INTO `tb_college`
    (`col_name`, `col_intro`)
VALUES
    ('外国语学院', '学习歪果仁的语言的学院'),
    ('经济管理学院', '经世济民，治理国家；管理科学，兴国之道'),
    ('体育学院', '发展体育运动，增强人民体质');
```

When inserting data, note that primary keys cannot be duplicated. If the inserted data has the same primary key as an existing record in the table, the `insert` operation will produce a "Duplicated Entry" error message. Once again, if an `insert` operation omits certain columns, those columns must either have default values or allow `null`, otherwise an error will also occur. In business systems, to prevent the `insert` operation from affecting the performance of other operations (mainly the `select` operation discussed later), you can add `low_priority` between `insert` and `into` to lower the priority of the `insert` operation. This approach also applies to the `delete` and `update` operations discussed below.

Suppose there is a table named `tb_temp` with two columns `a` and `b`, which store college names and college introductions respectively. We can also retrieve data from the `tb_temp` table through a query operation and insert it into the college table, as shown below. The `select` in the code is the DQL we mentioned earlier, which will be explained in detail in the next lesson.

```SQL
INSERT INTO `tb_college`
    (`col_name`, `col_intro`)
SELECT `a`, `b`
  FROM `tb_temp`;
```

### Delete Operation

If you need to delete data from a table, you can use the `delete` operation, which can help delete specified rows or all rows. For example, to delete the college with ID `1`, you can use the following SQL.

```SQL
DELETE
  FROM `tb_college`
 WHERE col_id=1;
```

Note that the `where` clause in the `delete` operation above is used to specify conditions - only rows that meet the conditions will be deleted. If we accidentally write the following SQL, it will delete all records in the college table, which is extremely dangerous and typically would not be done in practice.

```SQL
DELETE
  FROM `tb_college`;
```

It should be noted that even if all data is deleted, the `delete` operation will not delete the table itself, nor will it reset the AUTO_INCREMENT field back to its initial value. If you need to delete all data and reset the AUTO_INCREMENT field, you can use `truncate table` to perform a table truncation. The essence of `truncate` is to drop the original table and recreate it, which is actually faster because it does not need to delete data row by row. However, please remember that using `truncate table` to delete data is very dangerous because it deletes all data, and since the original table has been dropped, recovering accidentally deleted data becomes extremely difficult.

### Update Operation

If you need to modify data in a table, you can use the `update` operation, which can update specified rows or all rows. For example, to change "杨过" to "杨逍" in the student table, assuming "杨过"'s student ID is `1001`, the code is as follows.

```SQL
UPDATE `tb_student`
   SET `stu_name`='杨逍'
 WHERE `stu_id`=1001;
```

Note the `where` clause in the SQL above. We use the student ID as the filter condition to find the corresponding student, then change the name to "杨逍" through the assignment operation. Why don't we use the name directly as the filter condition? That is because there could be multiple students named "杨过" in the student table. If we used stu_name as the filter condition, our `update` operation might update multiple records at once, which is obviously not what we want. Another thing to note is the `set` keyword in the `update` operation. In SQL, `=` does not represent assignment but is an equality comparison operator. Only when `=` appears after the `set` keyword does it have assignment capability.

If we want to modify both the student's name and birthday simultaneously, we can slightly modify the `update` statement above, as shown below.

```SQL
UPDATE `tb_student`
   SET `stu_name`='杨逍'
     , `stu_birth`='1975-12-29'
 WHERE `stu_id`=1001;
```

The `update` statement can also use queries to obtain data and use it to update specified table data. Interested readers can explore this on their own. When writing `update` statements, there is usually a `where` clause because updating an entire table is almost never done in practice - this is something you must keep in mind.
