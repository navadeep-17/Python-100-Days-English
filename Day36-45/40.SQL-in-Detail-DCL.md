## SQL in Detail - DCL

Database servers typically contain very important data, and access control can be used to ensure the security of this data. DCL is designed to solve this problem - it can grant access permissions to specified users or revoke specified permissions from them. DCL is very important for database administrators because user permission management is directly related to database security. In simple terms, we can use DCL to allow trusted users to access the database, block untrusted users from accessing the database, and minimize each user's permissions (giving users just enough permissions to do their work).

### Creating Users

We can use the following SQL to create a user and specify their access password.

```SQL
CREATE USER 'wangdachui'@'%' IDENTIFIED BY 'Wang.618';
```

The SQL above creates a user named wangdachui with the password Wang.618. This user can access the database server from any host, because the wildcard `%` (which matches any number of characters) is used after `@`. If we want to restrict wangdachui to only access the database server from hosts in the 192.168.0.x network segment, we can modify the SQL statement as follows.

```SQL
DROP USER IF EXISTS 'wangdachui'@'%';

CREATE USER 'wangdachui'@'192.168.0.%' IDENTIFIED BY 'Wang.618';
```

At this point, if we access the database server using the wangdachui account, we can barely do anything because the account has no operation permissions.

### Granting Permissions

We use the following statement to grant wangdachui the permission to query the college table (`tb_college`) in the school database.

```SQL
GRANT SELECT ON `school`.`tb_college` TO 'wangdachui'@'192.168.0.%';
```

We can also give wangdachui query permissions on all objects in the school database, as shown below.

```SQL
GRANT SELECT ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we want wangdachui to also have insert, delete, and update permissions, we can use the following approach.

```SQL
GRANT INSERT, DELETE, UPDATE ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we also want to grant wangdachui DDL execution permissions, we can use the following SQL.

```SQL
GRANT CREATE, DROP, ALTER ON `school`.* TO 'wangdachui'@'192.168.0.%';
```

If we want the wangdachui account to have all operation permissions on all objects in all databases, we can execute the following operation. However, in general, we would not do this because, as we mentioned earlier, permissions should be just enough - an ordinary account should not have such extensive permissions.

```SQL
GRANT ALL PRIVILEGES ON *.* TO 'wangdachui'@'192.168.0.%';
```

### Revoking Permissions

To revoke wangdachui's insert, delete, and update permissions on the school database, we can use the following operation.

```SQL
REVOKE INSERT, DELETE, UPDATE ON `school`.* FROM 'wangdachui'@'192.168.0.%';
```

To revoke all permissions, you can do it as follows.

```SQL
REVOKE ALL PRIVILEGES ON *.* FROM 'wangdachui'@'192.168.0.%';
```

It should be noted that the database may cache user permissions. After granting or revoking permissions, you can execute the following statement to make the new permissions take effect immediately.

```SQL
FLUSH PRIVILEGES;
```
