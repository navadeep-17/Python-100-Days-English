## New Features in MySQL

### JSON Type

Many developers often feel that structured storage lacks flexibility when using relational databases for data persistence, because all columns and their corresponding data types must be designed in advance. During business development and changes, having to modify the table structure is definitely a troublesome and painful thing. Starting from MySQL 5.7, MySQL introduced support for the JSON data type (MySQL 8.0 resolved the JSON logging performance bottleneck). Using the JSON type effectively breaks the boundary between relational and non-relational databases, bringing more convenience to data persistence operations.

The JSON type is mainly divided into two kinds: JSON objects and JSON arrays, as shown below.

1. JSON Object

```JSON
{"name": "骆昊", "tel": "13122335566", "QQ": "957658"}
```

2. JSON Array

```JSON
[1, 2, 3]
```

```JSON
[{"name": "骆昊", "tel": "13122335566"}, {"name": "王大锤", "QQ": "123456"}]
```

Where would JSON types be needed? Here is a simple example. Nowadays, many products support multiple login methods for users, such as phone number, WeChat, QQ, Sina Weibo, etc. However, we generally do not require users to provide all of this information. With the traditional design approach, you would need to design multiple columns corresponding to multiple login methods, and you might also need to allow these columns to contain null values, which is clearly not a great choice. On the other hand, if the product adds another login method, the previous table structure would inevitably need to be modified, which is even more painful. However, with the JSON type, the problem above can be easily solved. We can create the following design.

```SQL
CREATE TABLE `tb_test`
(
`user_id`    bigint unsigned,
`login_info` json,
PRIMARY KEY (`user_id`)
);

INSERT INTO `tb_test`
VALUES
    (1, '{"tel": "13122335566", "QQ": "654321", "wechat": "jackfrued"}'),
    (2, '{"tel": "13599876543", "weibo": "wangdachui123"}');
```

If you want to query a user's phone number and WeChat ID, you can use the following SQL statement.

```SQL
SELECT `user_id`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.tel')) AS phone
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.wechat')) AS wechat
FROM `tb_test`;
```

```
+---------+-------------+-----------+
| user_id | phone       | wechat    |
+---------+-------------+-----------+
|       1 | 13122335566 | jackfrued |
|       2 | 13599876543 | NULL      |
+---------+-------------+-----------+
```

Because JSON type is supported, MySQL also provides corresponding functions for processing JSON data, such as `json_extract` and `json_unquote` used above. Of course, the SQL above has a more convenient alternative syntax, as shown below.

```SQL
SELECT `user_id`
     , `login_info` ->> '$.tel' AS phone
     , `login_info` ->> '$.wechat' AS wechat
  FROM `tb_test`;
```

Here is another example. If our product wants to implement a user profiling feature (tagging users) and then recommend platform services or consumer goods based on user profiles, we can also use the JSON type to store user profile data. The sample code is shown below.

Create the profile tag table.

```SQL
CREATE TABLE `tb_tags`
(
`tag_id`   int unsigned NOT NULL COMMENT 'Tag ID',
`tag_name` varchar(20)  NOT NULL COMMENT 'Tag Name',
PRIMARY KEY (`tag_id`)
);

INSERT INTO `tb_tags` (`tag_id`, `tag_name`)
VALUES
    (1, '70后'),
    (2, '80后'),
    (3, '90后'),
    (4, '00后'),
    (5, '爱运动'),
    (6, '高学历'),
    (7, '小资'),
    (8, '有房'),
    (9, '有车'),
    (10, '爱看电影'),
    (11, '爱网购'),
    (12, '常点外卖');
```

Tag users.

```SQL
CREATE TABLE `tb_users_tags`
(
`user_id`   bigint unsigned NOT NULL COMMENT 'User ID',
`user_tags` json            NOT NULL COMMENT 'User Tags'
);

INSERT INTO `tb_users_tags`
VALUES
    (1, '[2, 6, 8, 10]'),
    (2, '[3, 10, 12]'),
    (3, '[3, 8, 9, 11]');
```

Next, let us explore the cleverness of the JSON type through a series of queries.

1. Query the user IDs of users who love watching movies (have tag `10`).

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE 10 MEMBER OF (`user_tags`->'$');
    ```

2. Query the user IDs of users born in the 80s (have tag `2`) who also love watching movies (have tag `10`).

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_CONTAINS(`user_tags`->'$', '[2, 10]');
    ```

3. Query the user IDs of users who love watching movies, were born in the 80s, or were born in the 90s.

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_OVERLAPS(user_tags->'$', '[2, 3, 10]');
    ```

> **Note**: The queries above use the `member of` predicate and two JSON functions. `json_contains` can check whether a JSON array contains specified elements, and `json_overlaps` can check whether a JSON array has overlapping parts with a specified array.

### Window Functions

MySQL has supported window functions since version 8.0. Most commercial databases and some open-source databases have long provided support for window functions, which are also sometimes called OLAP (Online Analytical Processing) functions - as the name suggests, they are related to statistics and analysis. To help you understand window functions, let us first discuss the concept of a window.

A window can be understood as a collection of records, and a window function is a special function executed on a set of records that satisfies certain conditions. The function is executed for each record within this window. Window functions are easily confused with the aggregate functions mentioned earlier. The main difference is that aggregate functions condense multiple records into a single record, while window functions are executed for each record without changing the number of records. Window functions are not just a few functions - they are a complete syntax, and functions are only part of that syntax. The basic syntax is as follows:

```SQL
<window_function> OVER (PARTITION BY <column_for_grouping> ORDER BY <column_for_sorting>  ROWS BETWEEN ... AND ...)
<window_function> OVER (PARTITION BY <column_for_grouping> ORDER BY <column_for_sorting> RANGE BETWEEN ... AND ...)
```

In the syntax above, the window function position can contain two types of functions:

1. Dedicated window functions, including: `lead`, `lag`, `first_value`, `last_value`, `rank`, `dense_rank`, and `row_number`, etc.
2. Aggregate functions, including: `sum`, `avg`, `max`, `min`, and `count`, etc.

Below are a few simple examples of using window functions. We will directly use the hrs database created in the previous lesson.

Example 1: Query the names and monthly salaries of employees ranked 4th to 6th by salary from highest to lowest.

```SQL
SELECT *
  FROM (SELECT `ename`
             , `sal`
             , ROW_NUMBER() over (ORDER BY `sal` DESC) AS `rk`
	      FROM `tb_emp`) AS `temp`
 WHERE `rk` between 4 and 6;
```

> **Note**: The function `row_number()` used above generates a row number for each record. In practice, you can replace it with `rank()` or `dense_rank()` as needed. The differences between these three can be found in the official documentation or by reading [this article on window functions](https://zhuanlan.zhihu.com/p/92654574). In versions of MySQL before 8, we could accomplish similar operations using the following approach.
>
> ```SQL
> select `rank`, `ename`, `sal` from (
>        select @a:=@a+1 as `rank`, `ename`, `sal`
>        from `tb_emp`, (select @a:=0) as t1 order by `sal` desc
> ) as `temp` where `rank` between 4 and 6;
> ```

Example 2: Query the names and department names of the two highest-paid employees in each department.

```SQL
select `ename`, `sal`, `dname`
from (
    select
        `ename`, `sal`, `dno`,
        rank() over (partition by `dno` order by `sal` desc) as `rank`
    from `tb_emp`
) as `temp` natural join `tb_dept` where `rank`<=2;
```

> Note: In versions of MySQL before 8, we could accomplish similar operations using the following approach.
>
> ```SQL
> select `ename`, `sal`, `dname` from `tb_emp` as `t1`
natural join `tb_dept`
where (
        select count(*) from `tb_emp` as `t2`
        where `t1`.`dno`=`t2`.`dno` and `t2`.`sal`>`t1`.`sal`
)<2 order by `dno` asc, `sal` desc;
> ```
