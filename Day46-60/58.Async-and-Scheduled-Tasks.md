## Asynchronous Tasks and Scheduled Tasks

In web applications, if a request performs a time-consuming operation or the execution time of the request is uncertain, and the user only needs to know that the server has received their request without needing the execution result immediately, such operations should be processed asynchronously. If we say that **using cache is the first principle of optimizing website performance**, then **asynchronizing time-consuming or uncertain-duration tasks is the second principle of website performance optimization**. Simply put, **anything that can be deferred should not be done immediately**.

Taking the SMS sending and file uploading to cloud storage discussed in the previous chapter as examples, the former is an operation with uncertain timing (because as the caller, we cannot determine the response time of the third-party platform), and the latter is a time-consuming operation (if the file is large or the third-party platform is unstable, both can lead to a lengthy upload time). Obviously, both operations are suitable for asynchronous processing.

In Python projects, we can use the third-party library Celery to handle asynchronous tasks and scheduled tasks. For content about Celery, please refer to the article [Developing Commercial Projects with Django](../Day91-100/95.使用Django开发商业项目.md).
