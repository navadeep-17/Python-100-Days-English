## Application of Concurrent Programming in Web Crawlers

In previous lessons, we have introduced multithreading, multiprocessing, and asynchronous programming in Python. Through these three approaches, we can implement concurrent or parallel programming, which on one hand can speed up code execution, and on the other hand can provide a better user experience. Crawler programs are typical I/O-intensive tasks. For I/O-intensive tasks, both multithreading and asynchronous I/O are good choices, because when a certain part of the program is blocked by I/O operations, other parts can still run, so we don't waste a lot of time in waiting and blocking. Below, we will use the example of scraping images from the "[360 Images](https://image.so.com/)" website and saving them locally to demonstrate the differences between crawlers written with single-threading, multithreading, and asynchronous I/O, while also making a simple comparison of their execution efficiency.

The "360 Images" website uses [Ajax](https://developer.mozilla.org/zh-CN/docs/Web/Guide/AJAX) technology on its pages, which is an asynchronous data loading and partial page refresh technique used by many websites. Simply put, the images on the page are all dynamically rendered through JavaScript code that asynchronously fetches JSON data, and the entire page also uses waterfall loading (loading more images as you scroll down). In the browser's "Developer Tools," we can find the data interface that provides dynamic content. As shown in the figure below, the image information we need is in the JSON data returned by the server.

<img src="res/20211205221352.png" style="zoom:40%;">

For example, to get images from the "beauty" channel, we can request the following URL, where the parameter `ch` represents the requested channel, and the parameter value `beauty` after `=` represents the "beauty" channel. The parameter `sn` is essentially a page number: `0` means the first page (with `30` images), `30` means the second page, `60` means the third page, and so on.

```
https://image.so.com/zjl?ch=beauty&sn=0
```

### Single-Threaded Version

Download `90` images from the "beauty" channel through the URL above.

```Python
"""
example04.py - Single-threaded version crawler
"""
import os

import requests


def download_picture(url):
    filename = url[url.rfind('/') + 1:]
    resp = requests.get(url)
    if resp.status_code == 200:
        with open(f'images/beauty/{filename}', 'wb') as file:
            file.write(resp.content)


def main():
    if not os.path.exists('images/beauty'):
        os.makedirs('images/beauty')
    for page in range(3):
        resp = requests.get(f'https://image.so.com/zjl?ch=beauty&sn={page * 30}')
        if resp.status_code == 200:
            pic_dict_list = resp.json()['list']
            for pic_dict in pic_dict_list:
                download_picture(pic_dict['qhimg_url'])

if __name__ == '__main__':
    main()
```

On macOS or Linux systems, we can use the `time` command to check the execution time and CPU utilization of the code above, as shown below.

```Bash
time python3 example04.py
```

Below is the execution result of the single-threaded crawler code on my computer.

```
python3 example04.py  2.36s user 0.39s system 12% cpu 21.578 total
```

Here we only need to note that the total time is `21.578` seconds, with a CPU utilization of `12%`.

### Multithreaded Version

We use the thread pool technique discussed earlier to modify the code above into a multithreaded version.

```Python
"""
example05.py - Multithreaded version crawler
"""
import os
from concurrent.futures import ThreadPoolExecutor

import requests


def download_picture(url):
    filename = url[url.rfind('/') + 1:]
    resp = requests.get(url)
    if resp.status_code == 200:
        with open(f'images/beauty/{filename}', 'wb') as file:
            file.write(resp.content)


def main():
    if not os.path.exists('images/beauty'):
        os.makedirs('images/beauty')
    with ThreadPoolExecutor(max_workers=16) as pool:
        for page in range(3):
            resp = requests.get(f'https://image.so.com/zjl?ch=beauty&sn={page * 30}')
            if resp.status_code == 200:
                pic_dict_list = resp.json()['list']
                for pic_dict in pic_dict_list:
                    pool.submit(download_picture, pic_dict['qhimg_url'])


if __name__ == '__main__':
    main()
```

Execute the following command.

```Bash
time python3 example05.py
```

The execution result is as follows:

```
python3 example05.py  2.65s user 0.40s system 95% cpu 3.193 total
```

### Asynchronous I/O Version

We use `aiohttp` to modify the code above into an asynchronous I/O version. To implement network resource fetching and file writing operations in an asynchronous I/O manner, we first need to install the third-party libraries `aiohttp` and `aiofile`, with the commands shown below.

```Bash
pip install aiohttp aiofile
```

The usage of `aiohttp` was briefly introduced in a previous lesson. The `async_open` function in the `aiofile` module is roughly the same as Python's built-in `open` function, except that it supports asynchronous operations. Below is the asynchronous I/O version of the crawler code.

```Python
"""
example06.py - Asynchronous I/O version crawler
"""
import asyncio
import json
import os

import aiofile
import aiohttp


async def download_picture(session, url):
    filename = url[url.rfind('/') + 1:]
    async with session.get(url, ssl=False) as resp:
        if resp.status == 200:
            data = await resp.read()
            async with aiofile.async_open(f'images/beauty/{filename}', 'wb') as file:
                await file.write(data)


async def fetch_json():
    async with aiohttp.ClientSession() as session:
        for page in range(3):
            async with session.get(
                url=f'https://image.so.com/zjl?ch=beauty&sn={page * 30}',
                ssl=False
            ) as resp:
                if resp.status == 200:
                    json_str = await resp.text()
                    result = json.loads(json_str)
                    for pic_dict in result['list']:
                        await download_picture(session, pic_dict['qhimg_url'])


def main():
    if not os.path.exists('images/beauty'):
        os.makedirs('images/beauty')
    loop = asyncio.get_event_loop()
    loop.run_until_complete(fetch_json())
    loop.close()


if __name__ == '__main__':
    main()
```

Execute the following command.

```Bash
time python3 example06.py
```

The execution result is as follows:

```
python3 example06.py  0.82s user 0.21s system 27% cpu 3.782 total
```

### Summary

By comparing the execution results of the three code snippets above, we can draw a conclusion: both multithreading and asynchronous I/O can improve the performance of crawler programs, because we don't waste time waiting and blocking caused by I/O operations. The `time` command results also tell us that the single-threaded code only achieves `12%` CPU utilization, while the multithreaded version reaches `95%`. The single-threaded version took about `21` seconds, while both the multithreaded and asynchronous I/O versions completed in only `3` seconds. Additionally, with similar running times, the multithreaded code consumed more CPU resources than the asynchronous I/O code, because thread scheduling and switching also require CPU time. At this point, the advantages and disadvantages of the three approaches for I/O-intensive tasks are already clear at a glance - though of course, these are just the results from my computer. If network conditions are not ideal or the target website responds slowly, the advantages of multithreading and asynchronous I/O will be even more pronounced. Interested readers can experiment on their own.
