## Concurrent Programming in Python - 2

In the previous lesson, we mentioned that due to the existence of the GIL, multithreading in CPython cannot leverage multi-core CPU advantages. If you want to break through the GIL limitation, you can consider using multiprocessing. For multiprocess programs, each process has its own GIL, so multiprocessing is not affected by the GIL. So, how should we create and use multiple processes in Python programs?

### Creating Processes

In Python, you can create processes based on the `Process` class. Although processes and threads have fundamental differences, the usage of the `Process` class is very similar to the `Thread` class. When creating objects using the `Process` class constructor, you also pass a function through the `target` parameter to specify the code the process should execute, and the `args` and `kwargs` parameters can specify the parameter values for that function.

```Python
from multiprocessing import Process, current_process
from time import sleep


def sub_task(content, nums):
    # Get the current process object through the current_process function
    # Get the process ID and name through the process object's pid and name attributes
    print(f'PID: {current_process().pid}')
    print(f'Name: {current_process().name}')
    # From the output below, it's not hard to see that each process has its own nums list.
    # Processes don't share memory by nature.
    # When creating child processes, the parent process's data structures are copied.
    # All three processes get 20 from pop(0).
    counter, total = 0, nums.pop(0)
    print(f'Loop count: {total}')
    sleep(0.5)
    while counter < total:
        counter += 1
        print(f'{counter}: {content}')
        sleep(0.01)


def main():
    nums = [20, 30, 40]
    # Create and start processes to execute the specified function
    Process(target=sub_task, args=('Ping', nums)).start()
    Process(target=sub_task, args=('Pong', nums)).start()
    # Execute sub_task function in the main process
    sub_task('Good', nums)


if __name__ == '__main__':
    main()
```

> **Note**: The code above uses the `current_process` function to get the current process object, and then uses the process object's `pid` attribute to get the process ID. In Python, using the `getpid` function from the `os` module can achieve the same effect.

If you prefer, you can also use the `fork` function from the `os` module to create processes. When this function is called, the operating system automatically copies the current process (parent process) to create a child process. The parent process's `fork` function returns the child process's ID, while the `fork` function in the child process returns `0`. In other words, this function is called once but returns two different values in the parent and child processes. Note that Windows does not support the `fork` function. If you are using Linux or macOS, you can try the code below.

```Python
import os

print(f'PID: {os.getpid()}')
pid = os.fork()
if pid == 0:
    print(f'Child process - PID: {os.getpid()}')
    print('Todo: Code to execute in the child process')
else:
    print(f'Parent process - PID: {os.getpid()}')
    print('Todo: Code to execute in the parent process')
```

In short, we still recommend creating and using multiple processes through three methods: directly using the `Process` class, inheriting the `Process` class, and using process pools (`ProcessPoolExecutor`). Unlike the `fork` function above, these three methods ensure code compatibility and portability. The specific approach is quite similar to the methods for creating and using multithreading discussed earlier, so we won't elaborate further here.

### Comparing Multiprocessing and Multithreading

For I/O-intensive tasks like web crawlers, using multiprocessing doesn't offer much advantage. However, for CPU-intensive tasks, multiprocessing shows significant efficiency improvements compared to multithreading. We can prove this with the code below. The following code uses both multithreading and multiprocessing approaches to determine whether a set of large integers are prime numbers. This is clearly a CPU-intensive task. We distribute the tasks across multiple threads and multiple processes to speed up code execution, and let's see how the multithreading and multiprocessing code differ in their actual performance.

Let's first implement a multithreaded version, as shown below.

```Python
import concurrent.futures

PRIMES = [
    1116281,
    1297337,
    104395303,
    472882027,
    533000389,
    817504243,
    982451653,
    112272535095293,
    112582705942171,
    112272535095293,
    115280095190773,
    115797848077099,
    1099726899285419
] * 5


def is_prime(n):
    """Check if a number is prime"""
    for i in range(2, int(n ** 0.5) + 1):
        if n % i == 0:
            return False
    return n != 1


def main():
    """Main function"""
    with concurrent.futures.ThreadPoolExecutor(max_workers=16) as executor:
        for number, prime in zip(PRIMES, executor.map(is_prime, PRIMES)):
            print('%d is prime: %s' % (number, prime))


if __name__ == '__main__':
    main()
```

Assuming the code above is saved in a file named `example.py`, on Linux or macOS systems, you can use the `time python example.py` command to execute the program and get operating system statistics about execution time. On my macOS, the last line of one run's output is shown below.

```

```

From the results, we can see that the multithreaded code can only bring CPU utilization to 100%, which already proves that multithreaded code cannot leverage multi-core CPU features to speed up code execution. Now let's look at the multiprocess version, where we replace the thread pool (`ThreadPoolExecutor`) with a process pool (`ProcessPoolExecutor`).

### Inter-Process Communication

Before explaining inter-process communication, let me give you a task: start two processes, one outputting "Ping" and the other outputting "Pong," and when the total number of "Ping" and "Pong" outputs reaches 50, end the program. Sounds very simple, right? But when actually writing the code, since multiple processes cannot directly exchange data through shared memory like multiple threads can, the code below will not achieve the result we want.

```Python
from multiprocessing import Process
from time import sleep

counter = 0


def sub_task(string):
    global counter
    while counter < 50:
        print(string, end='', flush=True)
        counter += 1
        sleep(0.01)


def main():
    Process(target=sub_task, args=('Ping', )).start()
    Process(target=sub_task, args=('Pong', )).start()


if __name__ == '__main__':
    main()
```

The code above looks fine, but the final result is that "Ping" and "Pong" each output 50 times. Let me remind you again: when we create processes in a program, child processes copy the parent process and all its data structures. Each child process has its own independent memory space, which means there is a separate `counter` variable in each of the two child processes, and both will count from `0` to `50`, so the result is predictable. A relatively simple way to solve this problem is to use the `Queue` class from the `multiprocessing` module, which is a queue that can be shared between multiple processes. It is implemented using the operating system's underlying pipes and semaphore mechanisms, as shown in the code below.

```Python
import time
from multiprocessing import Process, Queue


def sub_task(content, queue):
    counter = queue.get()
    while counter < 50:
        print(content, end='', flush=True)
        counter += 1
        queue.put(counter)
        time.sleep(0.01)
        counter = queue.get()


def main():
    queue = Queue()
    queue.put(0)
    p1 = Process(target=sub_task, args=('Ping', queue))
    p1.start()
    p2 = Process(target=sub_task, args=('Pong', queue))
    p2.start()
    while p1.is_alive() and p2.is_alive():
        pass
    queue.put(50)


if __name__ == '__main__':
    main()
```

> **Tip**: The `get` method of the `multiprocessing.Queue` object blocks by default when the queue is empty, and won't return until data is obtained. If you don't want the method to block or need to specify a blocking timeout, you can set the `block` and `timeout` parameters.

The code above uses the `get` and `put` methods of the `Queue` class to allow three processes (`p1`, `p2`, and the main process) to share data. This is what's called inter-process communication. Through this approach, when the value retrieved from the `Queue` is already greater than or equal to `50`, `p1` and `p2` will exit the `while` loop, thereby terminating process execution. The loop on line 22 is there to wait for one of the `p1` and `p2` processes to finish. At that point, the main process still needs to put a value greater than or equal to `50` into the `Queue`, so that the other process that hasn't finished yet will also terminate upon reading this value that is greater than or equal to `50`.

There are many other ways for inter-process communication. For example, sockets can also be used for communication between two processes, and these two processes don't even need to be on the same machine. Interested readers can explore this on their own.

###  Summary

In Python, we can also use the `call` function from the `subprocess` module to execute other commands to create child processes, which is essentially calling other programs within our program. We won't discuss this knowledge here for now; interested readers can research it on their own.

For Python developers, the following situations call for considering multithreading:

1. The program needs to maintain many shared states (especially mutable states). Lists, dictionaries, and sets in Python are all thread-safe (multiple threads operating on the same list, dictionary, or set simultaneously won't cause errors or data problems), so the cost of maintaining shared state using threads rather than processes is relatively small.
2. The program spends a lot of time on I/O operations, doesn't have heavy parallel computing needs, and doesn't need to occupy too much memory.

The following situations call for considering multiprocessing:

1. The program executes CPU-intensive tasks (such as audio/video encoding and decoding, data compression, scientific computing, etc.).
2. The program's input can be divided into blocks in parallel, and the computation results can be merged.
3. The program has no limitations on memory usage and does not strongly depend on I/O operations (such as reading and writing files, sockets, etc.).
