## Software Testing and Automated Testing

### Software Testing Overview

Software testing is a process used to facilitate the identification of software correctness, completeness, security, and quality. It is the process of operating a program under specified conditions to discover errors, measure software quality, and evaluate whether it meets design requirements.

#### Testing Methods

Black-box testing: Tests the functionality of an application rather than its internal structure or workings. Testers do not need knowledge of the application's code, internal structure, or programming language. They only need to know what the system is supposed to do - that is, given a specific input, a certain output should be obtained. Test cases are designed based on the functions the application should perform, according to specifications, rules, or requirements. Testers select valid and invalid inputs to verify correct output. This testing method is suitable for most software testing, such as integration testing and system testing.

White-box testing: Tests the internal structure or workings of an application, rather than testing the application's functionality (i.e., black-box testing). In white-box testing, test cases are designed from a programming language perspective. Testers input data to verify the data flow path through the program, and determine the appropriate output, similar to testing nodes in a circuit.

Due to time and cost constraints, one of the most critical questions in software testing is: "**Among all possible test cases, which subset can find the most errors?**" Therefore, when designing test cases, white-box testing focuses on the degree of program logic coverage (statement coverage, condition coverage, branch coverage), while black-box testing can use equivalence class partitioning, boundary value analysis, cause-effect graph analysis, error guessing, and other methods to design test cases.

#### Types (Phases) of Testing

Unit testing: Tests the individual components of software. Its purpose is to verify the correctness of the most basic units of software. The object of testing is the smallest unit of software design - functions.

Integration testing: Assembles program modules using appropriate integration strategies and tests the correctness of system interfaces and integrated functionality. Its main purpose is to check whether the interfaces between software units are correct. The objects of integration testing are modules that have already passed unit testing.

System testing: System testing mainly includes functional testing, interface testing, reliability testing, usability testing, and performance testing.

Regression testing: Testing activities performed to detect errors introduced by code modifications. Regression testing is an important part of the software maintenance phase. Research has shown that regression testing accounts for more than 1/3 of the total cost of the software lifecycle.

#### Test-Driven Development (Agile Testing)

Test-driven development includes the following three steps:

1. Write automated tests for unimplemented new features or improvements.
2. Provide the minimum amount of code that passes all defined tests.
3. Refactor the code to meet required quality standards.

The benefits of test-driven development are that it can effectively prevent software regression and provide higher quality code. Also, acceptance testing should be performed by the customer. The customer designs acceptance tests based on usage scenarios to objectively and impartially confirm whether the application meets their requirements. Features that pass unit tests, and even system tests, may not necessarily pass the customer's acceptance tests.

#### Testing for Internet and Mobile Applications

Internet application testing strategies:

1. Presentation layer testing (content testing, site structure testing, user environment (browsers, operating systems, etc.))
2. Business layer testing (performance, data validation, transactions, external services)
3. Persistence layer testing (response time, data integrity, fault tolerance)

Mobile application testing strategies:

1. Real device testing
2. Emulator-based testing

### Unit (Module) Testing

Python's standard library includes the unittest module for writing unit tests. For executing tests, it is recommended to use [pytest](https://docs.pytest.org/en/latest/) or nose2. pytest is a test execution tool that can automatically search for and execute tests, and it outputs detailed error reports. For unit testing, you can read ["Python's Must-Know Unit Testing Framework - unittest"](https://blog.csdn.net/huilan_same/article/details/52944782).



You can install the [testfixtures](https://pypi.org/project/testfixtures/) library to assist with unit testing. It integrates various typical fixtures, providing modules for generating directories, changing system dates, and creating mock objects. These modules can help us isolate unit tests from the environment they depend on. [mock](https://pypi.org/project/mock/) is a library that replaces objects that the test object depends on with virtual objects. During testing, we can specify the return value of virtual objects when called and whether exceptions occur.

tox conveniently prepares the environment needed for test execution. tox sets up test environments in multiple virtualenv environments, then executes tests in these environments and displays the results. It can unify test tool options and environment variables, so we only need to execute the tox command to easily complete the required tests.

##### Web - [Selenium](<https://docs.seleniumhq.org/>)

Selenium is a browser-driven testing tool suite for automating functional testing and integration testing of web applications. Like users who use browsers, Selenium can perform mouse operations in the browser, input text in forms, verify form values, etc. By leveraging this, manual operations can be turned into automated operations.

1. Selenium Advantages

  - Easy creation of automated test cases. Selenium provides the Selenium IDE tool, which can capture mouse and keyboard operations, and then replay them, making it simple to create test cases.
  - Supports multiple browsers and operating systems.

2. Selenium Components

  - [Selenium IDE](https://www.seleniumhq.org/projects/ide/)
  - [Selenium Remote Control](https://www.seleniumhq.org/projects/remote-control/)
  - [Selenium WebDriver](https://www.seleniumhq.org/projects/webdriver/)

3. Collaboration with Continuous Integration Tools

   Continuous integration refers to frequently integrating code into the main branch. Its benefits are mainly two-fold:

   - Quickly discover errors. By integrating into the main branch with every small update, errors can be found quickly and are relatively easy to locate.
   - Prevent branches from deviating significantly from the main branch. If integration is not done frequently while the main branch keeps updating, it will become increasingly difficult to integrate later, or even impossible.

   The purpose of continuous integration is to enable rapid product iteration while maintaining high quality. Its core measure is that code must pass automated tests before being integrated into the main branch. If even one test case fails, integration cannot proceed. Programming master Martin Fowler once said: "Continuous integration doesn't get rid of bugs, but it does make them dramatically easier to find and remove."

   You can install the "Seleniumhq Plugin" in Jenkins, so that test cases created with Selenium IDE can be saved in HTML format and provided to Jenkins for use. The basic steps are:

   - Download the test suite and test cases from the version control system on the test execution machine.

   - Download the Selenium Server on the test execution machine.

   - Install the "Seleniumhq Plugin" from Jenkins' "System Management" under "Plugin Management".

   - Configure the "HTMLSuite Runner" under "Selenium Remote Control" in Jenkins' "System Management" under "System Settings".

   - Create a Jenkins test task and configure it, including: browser, starting URL, test suite, and test result output file.

   Once configured, you can execute Jenkins' "Build Now".

Besides Selenium, [WebTest](https://pypi.org/project/WebTest/), [Splinter](<https://splinter.readthedocs.io/en/latest/>), and [RobotFramework](<https://robotframework.org/>) are also options for web testing. WebTest can execute simulated requests against WSGI applications and obtain results - basically all WSGI application testing can use it; Splinter is a wrapper around Selenium that is more convenient and simple to use.
